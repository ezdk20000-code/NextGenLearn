# Бриф для ИИ-бэкендера: NextGenLearn

Этот файл — промпт. Передай его модели (Claude Code, Cursor, Windsurf) **вместе с репозиторием**:
модель должна видеть `db/schema.sql`, `api/openapi.yaml`, `src/lib/fsrs.ts` и `src/data/networks.ts`.
Это источники правды; бриф лишь объясняет, как их собрать в работающий сервер.

---

Ты — ведущий бэкенд-инженер проекта NextGenLearn (NGL). NGL учит любого человека любой теме:
по запросу «хочу понять X» строит граф понятий, уроки, интерактивные лаборатории и карточки
для интервального повторения, затем ведёт ученика по плану.

## Источники правды (не придумывай свои)

| Файл | Что фиксирует |
|---|---|
| `db/schema.sql` | Схема PostgreSQL 16. Меняй только миграциями, объясняя причину. |
| `api/openapi.yaml` | Контракт REST API. Фронтенд пишется по нему. |
| `src/lib/fsrs.ts` + `tests/fsrs.test.ts` | Эталонный FSRS-4.5. Сервер обязан давать **те же числа**. |
| `src/data/networks.ts` | Пример полностью собранного трека: так должен выглядеть результат генерации. |
| `src/pages/*Lab.tsx` | Три лаборатории — образцы примитивов `stepper`, `param_explorer`, `builder`. |

## Стек

- TypeScript, Node 22, **Fastify** + `zod`; валидация запросов и ответов из `openapi.yaml`.
- PostgreSQL 16, запросы через **Drizzle ORM** или `kysely`; миграции из `db/schema.sql`.
- Фоновые задачи: **pg-boss** (очередь прямо в Postgres; Redis на старте не нужен).
- Генерация контента: Claude API со structured output (JSON-схемы блоков из `openapi.yaml`).
- Один язык с фронтендом, поэтому `src/lib/fsrs.ts` и движки лабораторий переиспользуются на сервере как есть.

## Модули

1. **Tracks / генерация.** `POST /tracks` создаёт трек со статусом `generating` и ставит задачу в очередь.
   Конвейер: (1) граф 8–20 узлов с предпосылками, проверка на ацикличность, раскладка координат по tier;
   (2) уроки первых двух уровней; (3) 1–3 лаборатории из примитивов; (4) карточки из уроков.
   Каждый шаг публикуется в SSE `/tracks/{id}/events`. Уроки остальных узлов генерируются лениво.
   Всё, что вернула модель, валидируется по схеме; при ошибке — до 2 повторов, потом `failed`.
2. **Lessons.** Сервер хранит правильные ответы и не отдаёт их клиенту. `feynman`-ответы оценивает ИИ
   по рубрике «ключевые идеи урока»: отзыв в 2–3 предложения, без оценки «хорошо/плохо» в лоб.
3. **Labs.** Для каждого примитива — детерминированный движок `reduce(state, action) → state`.
   Клиент присылает журнал действий; сервер переигрывает его и сам решает, пройдено ли.
4. **Reviews (FSRS).** `POST /reviews` в одной транзакции: читает `user_cards` с блокировкой строки,
   вызывает `review()` из `fsrs.ts`, обновляет карточку, пишет `review_logs`, начисляет XP.
   Очередь: `due_at <= now()`, сортировка по текущей R по возрастанию.
5. **Plan.** Каждый день: сначала повторение (≈ 25 с на карточку), затем следующий доступный урок,
   затем лаборатория, на остаток — фокус-сессия; всё в пределах `daily_minutes`.
6. **Me.** XP — сумма `xp_events`; уровень = 1 + floor(xp / 250); серия — подряд идущие дни
   с событиями в часовом поясе пользователя.

## Правила

- Мастерство узла и «витальность» не хранятся, а вычисляются (см. описание `GraphNode.mastery_pct`).
- Никаких выдуманных метрик. Каждое число на экране должно иметь формулу, которую можно объяснить ученику.
- Все пользовательские данные — только своего пользователя (проверка `owner_id` / `user_id` в каждом запросе).
- Тесты: FSRS (те же кейсы, что во фронтенде), ацикличность графа, переигрывание лабораторий, планировщик.
